# AR-12 — Owner-friendly rules: choosing things, built-in views, plain words, grow-into-it, help

Design: `docs/designs/APP-REDESIGN.md` section 4D. Build specs: `docs/build-specs/README.md`, `KIT.md`. Depends on
**AR-0a**. Runs alongside AR-11 and AR-0b. Risk: **settings + wording check + one additive migration**. No money,
permission or provider changes.

## Why
Chris: a first-time owner must not need accounting words or know how the system works inside. Choices should be
easy to make, lists should already have the views a beginner needs, and features should show up only when the
business needs them.

## Decisions already made (do not re-decide)
- **Dropdowns are native `<select>`** styled with the kit (best on phones, screen readers and keyboards). Long lists
  of records use the searchable picker.
- **The stricter word list applies to redesigned pages only** (the files in `docs/build-specs/migrated-pages.json`
  and everything in `src/components/kit/`). Today ~280 places on older desk pages say "invoice"; they are fixed when
  each page is redesigned, and AR-10 turns the list on for every desk page.
- **Hidden is never blocked.** A hidden feature's pages still open by URL, stay in search and the command bar, and
  keep working. Hiding only removes menu entries and tabs.
- **Feature switches are stored as one new list** `BusinessSettings.shownFeatures String[] @default([])` (additive
  migration `20261026000000_shown_features`). Budget envelopes are also shown automatically while the existing
  `cashBudgetEnabled` setting is on (it is in use), so nothing Chris already uses disappears.
- **Saved views use the existing O-7 workspace store** (`src/domains/workspace`, `SAVED_VIEW_ROUTES`, max 20). No new
  table.
- **The Practice link** points at the testing app through a new server setting `PRACTICE_APP_URL`. Until Chris sets
  it, the link is hidden (checklist row below). Never hard-code the address.

## Steps (in order)

1. **Selection components** in `src/components/kit/` (tests in `tests/kit/`):
   - `SegmentedControl { name: string; label: string; options: { value: string; label: string }[]; value: string;
     onChange?: (v: string) => void }`. Renders a native radio group styled as joined buttons (2–4 options; throws
     in development with more than 4). Keyboard: arrow keys move.
   - `Select { name; label; options; value?; placeholder?; required?; error? }`. Native `<select>` with
     `rounded-field`, `min-h-11`, chevron, the label above, the error under it (`aria-describedby`).
   - `SearchablePicker { name: string; label: string; search: (q: string) => Promise<{ id: string; label: string;
     detail?: string }[]>; value?: { id: string; label: string }; addNew?: { label: string; href: string } }`. Phone:
     opens a `Sheet`; desktop: Radix Popover. Inside: `cmdk` input ("Type 2 letters to search"), results after 2
     characters, debounce 200 ms, "+ {addNew.label}" last. Writes a hidden input `name` with the id.
   - `OptionCards { name; label; options: { value: string; title: string; line: string; info?: GlossaryKey;
     recommended?: boolean }[]; value }`. A radio group of cards; the recommended one shows a small
     "Recommended" pill (good tone).
   - `Switch { label: string; checked: boolean; action: (fd: FormData) => Promise<{ ok: boolean; error?: string }>;
     fields?: Record<string,string>; info?: GlossaryKey; onText: string; offText: string }`. `role="switch"`, saves on
     toggle (no Save button), optimistic through AR-11's `useOptimisticAction` (if AR-11 is not merged yet, use
     `useOptimistic` directly and switch later), success toast = `onText`/`offText`.
2. **Built-in views.** `src/components/kit/built-in-views.ts`:
   `BUILT_IN_VIEWS: Record<ListKey, { id: string; label: string; params: Record<string, string>; roles?: Role[] }[]>`
   with exactly these (params are the list's own URL params; if a list does not support a param yet, the view is
   added by the unit that redesigns that list — mark it `pending: true` and Toolbar hides pending views):
   - `billing`: "Past due" {status: past-due}; "Due this month" {status: open, due: this-month}; "Autopay off"
     {status: open, autopay: off}.
   - `customers`: "Renting now" {status: active}; "Owe money" {owes: yes}; "Property managers" {kind: pm}
     (shown only when the property-managers feature is shown).
   - `rentals` (agreements list): "Starting this week" {starts: this-week}; "Ending this month" {ends: this-month};
     "Waiting for signature" {status: awaiting-signature}.
   - `inventory`: "Ready to rent" {status: AVAILABLE}; "Needs repair" {status: MAINTENANCE}; "Out with customers"
     {status: RENTED}; "Coming back" {status: AWAITING_PICKUP}.
   - `jobs`: "My visits today" {when: today, who: me} (STAFF and above); "Not scheduled" {when: none}.
   - `leads`: "New" {stage: new}; "Follow up today" {follow: today}.
   Add `billing` and `customers` to `SAVED_VIEW_ROUTES` with their real filter params so owners can save more. Wire
   `billing` into the Bills Toolbar (replace AR-0's inline built-in list with this registry). Test: every non-pending
   view's params pass that list's zod params schema.
3. **Plain words.** In `scripts/check-owner-wording.mjs` add `EVERYDAY_BANNED` (same shape as `BANNED`) applied only to
   the files described above, on top of `BANNED`:
   | pattern (case-insensitive) | say |
   |---|---|
   | `\binvoices?\b` | bill |
   | `\baccounts? receivable\|\breceivables?\b` | money customers owe you |
   | `\baccounts? payable\|\bpayables?\b` | bills you owe |
   | `\bjournal entr\w*\|\bledger\b\|\bposting\b` | your records |
   | `\baccrual\b\|\bcash basis\b` | "when billed" / "when paid" |
   | `\bdepreciat\w*` | equipment value going down |
   | `\bcapitaliz\w*` | count as equipment |
   | `\breconcil\w*` | check against your bank |
   | `\bwrite-?offs?\b\|\bwritten off\b` | give up on this bill |
   | `\bchargebacks?\b` | customer disputed the payment with their bank |
   | `\bdeferred revenue\|\bunearned\b` | rent paid in advance |
   | `\bpayment intents?\b\|\bcheckout session\|\bcron\b\|\bAPI\b\|\bsync(?:ed\|ing)?\b` | (say what happened) |
   | `(?<!rental )\bagreements?\b` | rental |
   | `\bSKUs?\b\|\basset numbers?\b` | item number / appliance number |
   The "For your accountant" pages (`src/app/desk/books/reports`, `exports`, `export`, `closing`, `assets`) are exempt
   by folder, written in the script with a comment. Add tests to `scripts/check-owner-wording.test.mjs`: each pattern
   hits and its plain alternative passes; "rental agreement" passes; exempt folder passes.
4. **Every status says what happens next.** `src/lib/status-next.ts`:
   `STATUS_NEXT: { bill: Record<BillPillKey, string>; rental: Record<RentalAgreementStatus, string>;
   visit: Record<JobStatus, string>; }` with these exact lines (unit test: every enum value present):
   - bill: open "Waiting for payment. A reminder goes out automatically before the due date."; past due "Late. Take
     payment or send a reminder."; payment
     failed "The card was refused. Take payment again or send a reminder."; paid "Paid in full. Nothing to do.";
     given up "You chose not to collect this bill."; cancelled "Cancelled. Nothing is owed."; refunded "Money was
     sent back to the customer."; draft "Not sent yet. Send it when it's ready."
   - rental: DRAFT "Not sent yet. Finish it and send it for signing."; AWAITING_SIGNATURE "Waiting for the customer
     to sign."; SCHEDULED "Signed. It starts on its start date."; ACTIVE "Renting now. Bills go out automatically.";
     ENDED "Finished. Make sure the appliances came back."; CANCELLED "Cancelled before it started."
   - visit: SCHEDULED "Booked. The customer gets a reminder the day before."; IN_PROGRESS "Happening now.";
     COMPLETED "Done."; CANCELLED "Cancelled. Nothing to do."
   Kit `StatusPill` gets an optional `next?: string`; when set, tapping the pill shows it in the InfoTip popover.
   The three AR-0 screens pass `next` for bill and rental pills.
5. **Visible automation.** Kit `AutomationLine { text: string }` — ⚙ icon + `text-sm text-ink-soft`, text always
   starts with "Automatic: ". Replace the ad-hoc line on the customer record (CUSTOMER-RECORD 4.5) with it. Later
   units add their own lines through this component only.
6. **Grow into it.** `src/domains/features/registry.ts` (pure) + `index.ts` (reads):
   ```ts
   export type FeatureKey = "team" | "propertyManagers" | "budget" | "accountantExports" | "bankStatements"
     | "spanishDocuments" | "phoneCosts";
   export const FEATURES: Record<FeatureKey, { label: string; line: string; hides: string[] /* href prefixes */;
     auto?: "teamOfTwo" | "hasPropertyManager" | "budgetInUse" }>
   export async function getShownFeatures(): Promise<Set<FeatureKey>>
   export function isHrefHidden(href: string, shown: Set<FeatureKey>): boolean
   ```
   | key | label | line | hides | shown when |
   |---|---|---|---|---|
   | team | Team | "Assign work, set what each person can see." | `/desk/dispatch`, `/desk/settings/permissions`, `/desk/approvals` | 2+ active team members (owner/admin/staff) — automatic |
   | propertyManagers | Property managers | "Many locations and tenants under one customer." | `/desk/customers/*/locations` menu items | any customer or lead with `isPropertyManager` — automatic |
   | budget | Budget envelopes | "Set money aside for each kind of spending." | `/desk/books/budget` | switched on, or automatically while `cashBudgetEnabled` is on |
   | accountantExports | Files for your accountant | "Download your records for an accountant or tax software." | `/desk/books/exports`, `/desk/books/export` | switched on |
   | bankStatements | Bank statements | "Upload bank statements and match them to your records." | `/desk/books/cash` | switched on |
   | spanishDocuments | Spanish documents | "Send quotes, rentals and bills in Spanish." | (settings sections only — AR-8) | switched on |
   | phoneCosts | Phone and texting costs | "See what calls and texts cost each month." | `/desk/settings/telecom` | switched on |
   - Automatic features are shown as switches that are on and locked, with the reason in an InfoTip ("Shown
     because you have 2 people on your team").
   - `src/lib/desk-navigation.ts`: filter nav items with `isHrefHidden` after the existing role/job-role filtering
     (never before it — a hidden feature never grants access).
   - **Settings → Features** section at `/desk/settings/features` (new page; `ScreenHeader` "Features", one line
     "Turn on more when your business needs it."; one `Switch` per feature). Save action
     `setFeatureShownAction` in `src/app/desk/settings/features/actions.ts`: OWNER only, locks the settings row
     (`SELECT … FOR UPDATE`), re-checks the actor (`assertActiveTeamActor`), adds/removes the key, records an audit
     row `settings.features` with `tx.auditLog.create` in the same transaction, the same way
     `src/domains/settings` writes its audit rows.
   - Tests: registry pure rules; integration on throwaway Postgres (owner turns one on/off, admin/staff refused,
     the nav hides and shows, a hidden page still opens by URL); migration passes `scripts/check-migrations.mjs`.
7. **"How do I…" guides.** `src/lib/help-guides.ts`: `HELP_GUIDES: { id; question; keywords: string[]; steps:
   [string, string, string]; href: string }[]` with these 15 (steps written against the redesigned screens; the
   browser spec opens each `href`): take a card payment; record cash or a check; send a payment reminder; refund a
   payment; give up on a bill; start a new rental; send a quote; schedule a delivery; schedule a pickup; add an
   expense; add a team member; retire an appliance; snooze a To do item; install the desk app; practice safely.
   AR-1's command bar searches `question` + `keywords`. Until AR-1, show them on a simple `/desk/help` page (a kit
   `DataTable` of questions; each opens a Sheet with the 3 steps and a "Go there" button).
8. **Practice link.** In Settings (Features page, below the switches) an `ActionButton` "Practice safely" opening
   `PRACTICE_APP_URL` in a new tab, with InfoTip "A copy of the app with made-up customers. Nothing you do there

   `PRACTICE_APP_URL` to the env list in `docs/ARCHITECTURE.md` (name and purpose only, never a value).
