# K-5 — Immutable, mapped Books export batches

Frozen K-5 scope against merged K-4 `3dd2dfca7be1e734b230c46d27f7d38fc089b9c9`, approved `docs/designs/BATCH-K.md` §3.6 and D-K11. **One substantial original subsection**: do not invent helper-sized subsections, and do not start dependent K-6 before K-5's complete engineering and gates.

1. OWNER/ADMIN can request QBO_JOURNAL_CSV, XERO_JOURNAL_CSV, GENERIC_JOURNAL_CSV or CASH_MOVEMENTS_CSV exports with a validated inclusive Colorado from/to range, DETAIL or DAILY_SUMMARY mode, and an optional already-exported filter; STAFF/CUSTOMER and inactive identities are refused by the domain and every route.
2. Before export, bounded source posting completes without errors; the export refuses uninitialized books, invalid/oversized dates, unsettled posting exceptions, unbalanced journals and any missing or inactive used-account mappings. No guessed account names or company credentials, no external accounting API.
3. Every target produces source-defined stable exact headers, dates, account mappings, integer-cent decimal amounts and safe spreadsheet-text escaping; QBO entry numbers/dates, Xero sign/account/tax columns, generic detailed journal and cash-movements category allocation have distinct tested formatters.
4. DETAIL contains all eligible source entries in stable date/entryNumber order; DAILY_SUMMARY nets each day's debit and credit per ledger account and remains balanced. Stripe payout skip settings are target-specific and the onlyNotYetExported filter is target-scoped, not globally suppressing a source.
5. Successful exports persist immutable ExportBatch bytes and SHA-256, bounded journal-entry provenance, output filename and creator; concurrent same-criteria requests and replay with onlyNotYetExported do not create duplicate exported entry identities, and existing export content never changes when mappings or source journals later change.
6. Owner/admin Books screen supports target/mode/date/filter, unmapped-account guidance and read-only export history with secure re-download; CSV GET enforces live authenticated accounting roles and no-store content headers. Existing /desk/books/export?month review remains working and unchanged.
7. Disposable PostgreSQL tests cover authorization, mapping and date guards, retries/concurrency, locked source batches, hash/byte integrity, cutoff and target scopes; focused formatter unit tests cover all target headers, daily net/cash allocations, payout flags and formula injection, and browser/axe/regression CI validates Books and export navigation. Maintain roadmap/owner guide/database/status and explicit real-provider trial-import acceptance.

## Limits and design rules

Reuse `ExportBatch`, `ExportBatchEntry`, `AccountExportMapping`, `JournalEntry`, `postPending`, `src/lib/csv.ts`, `formatCentsAsPlainDecimal`, `businessDateFromKey`, Books OWNER/ADMIN live role gates. Existing month-review export remains unchanged. No external accounting provider credentials, API writes, paid capacity, customer emails or financial activation. Imported trial-company results, owner mapping attestations and CPA signoff are separate real-world acceptance.

Architectural decisions: bounded source posting precedes a consistent PostgreSQL export transaction; guard with advisory locking, preserve immutable CSV payload, source journal IDs and source hash, fail closed on unmapped accounts or transaction integrity problems; protect all download/preview routes with actual session checks. Original full format contracts from §3.6 are mandatory, including daily net and cash movement allocation. Use existing target payout setting, not a new hardcoded flag.

## Publication rules

Commit plan-only card and execution packet **before code**. Build source/domain/UI/tests/docs as one PR, run focused locally where tooling permits, then exact-head CI (all unit/DB/browser shards, security, release policy, review), correct all failures together, and merge only on green. Read independent review before resolving threads; never treat authored tests as executed. Do not change `main` or `live` directly.
