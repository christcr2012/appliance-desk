# K-3 — Stripe evidence synchronization, clearing review and nightly books

Source: `docs/MASTER-ROADMAP.md` K-3; `docs/designs/BATCH-K.md` D-K4, D-K12, §§3.3–3.4, WU-K4 (approved). Parent prerequisites K-1A/B, K-2A/B are merged at `d96098cca7a8776bf11ee81aea9242c1cc451cfa`. This card freezes the original **one full, provider-specific subsection**, not invented helper units.

## Complete original acceptance — K-3
1. A bounded Stripe Balance Transactions importer pages the provider's transaction history with a persisted cursor, three-day overlap, stable-id upserts and safe reruns; cursor never skips an incomplete page or failed import.
2. Source-backed, integer-cent transaction evidence is recorded with currency, dates, fee, net, reporting category, source and payout identity; wrong currency or unknown types never produce guessed journal entries.
3. The existing balanced source rules and K-2 poster book fees, Stripe service charges, disputes and payouts exactly once; Stripe charge, refund and payment rows do not duplicate their existing receipt/refund journals; replay/concurrency and absent opening evidence fail safely.
4. A cutoff-based clearing check compares the journal's clearing balance through the **same yesterday-end Colorado timestamp** with the verified owner's opening Stripe balance plus the net of imported transactions through that timestamp; an actual one-cent mismatch creates an owner-visible deduplicated exception; a later payment does not make yesterday look wrong. Missing/incomplete provider coverage is UNKNOWN, not a false match or mismatch.
5. The daily `books-nightly` automation runs after database backup, reconciles imported evidence, posts pending journals and checks clearing with bounded effort, checked CRON authentication, durable run results and safe retries; no customer messaging, transfers, refunds, live charges or payments are initiated.
6. Synthetic provider pages and disposable PostgreSQL tests prove pagination, overlap, provider faults, concurrent repeats, posting categories, unknowns, permission/credential failures, yesterday cutoff and one-cent detection. CI/build/security/browser and checked real-world acceptance remain independent.

## Invariants and real-use boundary
The importer uses Stripe **read APIs only** but persists imported evidence to Appliance Desk. No production-provider or customer mutation is authorized by this engineering task; night automation remains off by default until owner-authorized activation. This opt-in is an operational prelaunch control, not a permanent restriction on entitled end users. Never activate LIVE Stripe, create test records in production, expose provider payloads, leak credentials, retry unknown money-out, or claim production acceptance. Failures leave cursor and journal safely recoverable.
