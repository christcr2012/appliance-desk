## Build contract

1. **Set lines on agreements.** `NewRentalLineInput.packageId?`. When set, inside the agreement-locked transaction:
   the package must be active; the chosen appliances must be exactly the package's machines — one per part, any
   individual machines of those types (`packagePartsProblem`, plain-words error naming what was picked). The line stores
   `packageId`; label and price are prefilled from the set on screen and stay editable (special deals). Prepay discount:
   unchanged rule (2+ machines on a line = set rate). Renewals copy `packageId`.
2. **Set lines on quotes.** `addEstimateLineItem` accepts `packageId` (active sets only); price stays what the owner types.
3. **Shared chooser** `src/components/desk/package-line-chooser.tsx` ("Rent as"), used by the rental wizard, the draft
   agreement page and the quote line form. Choices: `listPackagesForLines()` (active sets whose machines are all active).
4. **Old one-record sets.** To do category `OLD_SET_APPLIANCE` (owner/admin, medium): every non-archived, non-retired
   appliance still under the retired `washer-dryer-set` type → "Split WDS-0003 into separate machines (Washer + Dryer)"
   linking to `/desk/inventory/[id]/split`. `splitOldSetAppliance(userId, applianceId, parts)` (OWNER/ADMIN, actor
   re-check, appliance row lock, audit `appliance.split_old_set`): parts must match the `washer-dryer-set` package; the
   existing row becomes the first machine (keeps asset number, history, tax rows); each other machine is a new appliance
   with its own asset number, same status/condition/location/purchase-tax status; recorded cost and seller tax are split
   evenly (largest remainder, exact totals); an open rental assignment and an open custody stay are copied to the new
   machine, so the signed line, label and price never change. The appliance page links to the screen.
