# AR-11 — App feel foundations (installable, instant, never blank, keyboard and touch)

Design: `docs/designs/APP-REDESIGN.md` section 4A (and 4B for touch). Build specs: `docs/build-specs/README.md`,
`KIT.md` (sections 6 and 7). Depends on **AR-0a** (the kit). Can run alongside AR-0b and AR-12. Risk: **UI and
caching**. The service worker must never cache customer data. Read `docs/AI-PR-READ-FIRST.md` (preview safety,
auth/session).

## Why
Chris wants the desk to feel like installed software, not a website. That means it opens from its own icon,
responds to every tap at once, never shows a blank page, and works with a keyboard on a PC and with a thumb on a phone.

## Decisions already made (do not re-decide)
- **Desk app manifest is a static file** `public/desk.webmanifest`. It is not under `/desk/`, so the sign-in check in
  `src/proxy.ts` (matcher `/desk/:path*`) never blocks the browser fetching it. `src/app/desk/layout.tsx` sets
  `metadata.manifest = "/desk.webmanifest"`. The public site keeps `/manifest.webmanifest` unchanged.
- **Auto-refresh must not run up the database bill.** The database sleeps after 5 idle minutes (cost policy). So
  refreshing happens only while the tab is **visible** and the person has **touched, typed or scrolled in the last 10
  minutes**. Never refresh in the background.
- **The offline cache holds only the app's frame and static files.** It never stores a desk page's HTML, an RSC
  payload, an API response or an image upload. The driver's offline route is built with the route screen in **AR-5**
  (its card carries the exact cache rules).
- **View transitions need React 19.3** (`node_modules/next/dist/docs/01-app/02-guides/view-transitions.md`). The repo
  has 19.2.8. Step 0 upgrades `react`, `react-dom`, `@types/react` and `@types/react-dom` to exactly **19.3.0**
  (released 2026-09-09, so it meets the two-week rule; 19.3.1 is too new on 2026-10-25 — use it only if it is at
  least two weeks old on the day you start). Next 16.4.2 accepts `^19.0.0`.
- **No other new dependencies** in this card.

## Steps (in order)

0. **React 19.3.0.** `npm install --save-exact react@19.3.0 react-dom@19.3.0` and
   `npm install --save-exact --save-dev @types/react@19.3.0 @types/react-dom@19.3.0` (check the types version exists with
   `npm view @types/react-dom@19.3.0 version`; if not, use the newest `19.3.x` types at least two weeks old). Commit the
   lock file. Run `npx tsc --noEmit`, `npm run lint`, the unit suites locally that touch React components
   (`npx vitest run tests/kit`), and let CI run everything. Fix any type change in the same commit. If a test breaks
   because of the upgrade, fix the code, never the test's intent.
1. **Desk manifest** `public/desk.webmanifest`:
   ```json
   { "id": "/desk/today", "name": "Appliance Desk", "short_name": "Desk", "start_url": "/desk/today",
     "scope": "/desk/", "display": "standalone", "display_override": ["window-controls-overlay", "standalone"],
     "background_color": "#F7F5EC", "theme_color": "#123C2D",
     "icons": [ { "src": "/brand/icon-192.png", "sizes": "192x192", "type": "image/png", "purpose": "any" },
                { "src": "/brand/icon-512.png", "sizes": "512x512", "type": "image/png", "purpose": "any" },
                { "src": "/brand/icon-512.png", "sizes": "512x512", "type": "image/png", "purpose": "maskable" } ],
     "shortcuts": [
       { "name": "New quote", "url": "/desk/estimates/new" },
       { "name": "Take a payment", "url": "/desk/billing?status=open" },
       { "name": "Today's route", "url": "/desk/driver" },
       { "name": "Add an expense", "url": "/desk/expenses#add-expense" } ] }
   ```
   Add `id="add-expense"` to the wrapper of the existing add-expense form on `/desk/expenses`. In the desk layout's
   `viewport` export: `themeColor` light `#123C2D`, dark `#0c1e16` (media queries), `viewportFit: "cover"`.
   Test `tests/desk-manifest.test.ts`: valid JSON, every shortcut URL is a real route file, `start_url` inside `scope`.
2. **Window title** per screen: every migrated page exports `metadata.title` (the screen title); the root layout's
   title template is `"%s · Appliance Desk"` for desk pages (set in `src/app/desk/layout.tsx`).
3. **Never blank.** A `loading.tsx` in each desk area folder that has none, using kit `Skeleton` in the shape of the
   page type (list: header + tabs + 6 card rows; record: header + 4 stats + 3 cards). Replace the single
   `src/app/desk/loading.tsx` content with the list skeleton. Prefetch: kit `AreaTabs` and sidebar links use
   `next/link` (default prefetch); read `prefetching.md` and `instant-navigation.md` and follow their advice for
   dynamic pages.
4. **Optimistic helper** `src/components/kit/use-optimistic-action.ts`:
   `useOptimisticAction<T>(items: T[], reducer: (items: T[], change: Change) => T[], action: (fd: FormData) =>
   Promise<unknown>)` returning `{ items, run(change, fd, { undo?: () => Promise<void>,
   success: string }) }`. It wraps `useOptimistic` + `startTransition`; on failure (the action throws, or returns
   `{ ok: false, error }`) reverts and shows the danger toast — with `error` when returned, with the thrown error's
   message when it is one of this app's plain user-facing errors (e.g. `ApprovalInputError`, the snooze validation
   message), otherwise "That didn't save. Try again."; on success shows the toast with "Undo" for 10 seconds when `undo` is given. Refuses (throws in
   development) when called for an action whose ActionSpec has `confirm` (money). Unit-test revert, undo and the
   refusal. Use it for Today's snooze (replace AR-0's direct `useOptimistic` if AR-0b already merged).
5. **Live freshness** `src/components/kit/auto-refresh.tsx` (client): props `{ everySeconds?: number /* 60 */ }`.
   Calls `router.refresh()` (a) when the page becomes visible after being hidden ≥ 30 s, (b) every `everySeconds`
   while `document.visibilityState === "visible"` **and** the last `pointerdown`/`keydown`/`scroll` was < 10 minutes
   ago. Shows "Updated just now" / "Updated 3 min ago" (`relativeTime`) as small `text-xs text-ink-soft` text where the
   page puts it. Never refreshes while a form on the page has unsaved input (`form[data-dirty="true"]`) or a Sheet or
   dialog is open. Add it to Today, Bills and the customers list. Unit tests with fake timers for every condition.
6. **Offline frame.**
   - `src/app/offline/page.tsx`: static page (no data, no auth) "You're offline. Your changes are paused until the
     connection is back." with the badge logo and "Try again" (reload).
   - `public/desk-sw.js` (plain JS, no build step), scope `/desk/`: on install cache `/offline` and the icons;
     fetch handler: `/_next/static/*` and `/brand/*` → cache-first; navigations (`request.mode === "navigate"`) →
     network only, on network error respond with the cached `/offline`; **everything else passes through untouched
     and is never cached**. Version the cache name `desk-shell-v1`; delete other `desk-shell-*` caches on activate.
   - Register from `src/components/kit/register-sw.tsx` in the desk layout, only when
     `process.env.NODE_ENV === "production"` and `"serviceWorker" in navigator`. Under automation
     (`navigator.webdriver`) it registers **only** when `localStorage.getItem("desk-sw-test") === "on"` (wrapped in
     try/catch), so ordinary browser tests never get a worker. The offline browser test opts in: before the first
     navigation `context.addInitScript(() => localStorage.setItem("desk-sw-test", "on"))`, open `/desk/today`, wait
     until `await page.evaluate(() => navigator.serviceWorker.ready.then(() => !!navigator.serviceWorker.controller))`
     is true (reload once if the first load is not yet controlled), then `context.setOffline(true)`, navigate to
     `/desk/customers` and expect the cached offline page text, then `setOffline(false)` and "Try again" loads the
     page. Unrelated tests never set the flag. On sign-out (existing handler in `app-shell.tsx`) **keep** the `desk-shell-*`
     cache: it holds only the static offline page, icons and build files — nothing about the person — and the worker
     fills it only at install, so deleting it would leave the next session with no offline page. Sign-out deletes only
     per-person offline data (AR-5b's `indexedDB.deleteDatabase("desk-route")`, try/catch). The worker also re-adds
     `/offline` on `activate` and, on a navigation failure with no cached copy, tries `cache.add("/offline")` once next
     time it is online. Browser test: sign out → sign in → go offline → navigate → the offline page shows.
   - `OfflineBar` in the kit: listens to `online`/`offline`; when offline shows a sticky top bar "You're offline —
     changes are paused" (role `status`) and sets `data-offline="true"` on `<body>`; kit `ActionButton` of kind `form`
     is disabled while that attribute is set, with the reason "You're offline".
   - Test `tests/desk-sw.test.ts`: load the worker file in a fake `self` and check the three fetch rules, especially
     that a `/desk/customers/x` navigation response is **not** put in any cache.
7. **Keyboard** `src/components/kit/shortcuts.tsx` (client, mounted once in the desk layout, desktop only — skip
   when `(pointer: coarse)`): `/` focuses the page's search input (`[data-kit-search]`); `g` then `t|c|s|e|m` goes to
   `/desk/today`, `/desk/customers`, `/desk/dispatch`, `/desk/inventory`, `/desk/revenue` (Money overview until AR-3);
   `j`/`k` move a focus ring through `DataTable` rows, `Enter` opens the focused row, `Esc` closes the `SidePanel`
   (removes `open` from the URL); `?` opens a Sheet "Keyboard shortcuts" listing all of them. Ignore keys while typing
   in an input, textarea, select or contenteditable, or with Ctrl/Alt/Meta held (Ctrl K belongs to AR-1). Unit-test
   the key handling and the typing guard.
8. **Touch.** Kit `DataTable` phone cards: swipe left reveals the card's first two actions (pointer events,
   threshold 64 px, snaps back on tap elsewhere). The same actions stay on the card and in ⋯, so swipe is only a
   shortcut. Disabled under `prefers-reduced-motion`. Kit `Sheet` already uses `vaul`. `overscroll-behavior-y:
   contain` on the desk scroll container. Safe areas: `pb-[env(safe-area-inset-bottom)]` on the bottom bar, ActionBar
   and Fab; `pt-[env(safe-area-inset-top)]` on the phone top bar. **Pull to refresh** on list pages and Today (phone
   only, `(pointer: coarse)`): kit `PullToRefresh` wrapping the list — when the page is scrolled to the top and the
   finger drags down more than 72 px, show a small spinner row "Release to refresh" → on release call
   `router.refresh()` inside `startTransition` and show "Updated just now" when done. Not shown under reduced motion
   (a "Refresh" item appears in the page ⋯ instead). Unit-test the threshold logic with synthetic pointer events.
9. **Chrome polish** in `globals.css` (desk only, under `.desk-app` on the desk layout root): `user-select: none` on
   `button, [role=tab], [role=menuitem], nav a`; `accent-color: var(--color-primary)`; `-webkit-tap-highlight-color:
   transparent`; pressed state `active:scale-[0.98]` on kit buttons (none under reduced motion).
10. **State memory** `src/components/kit/remember-list.tsx`: on list pages, saves `location.search` and `scrollY` to
    `sessionStorage` under `list:<pathname>` when leaving. Kit `AreaTabs`, sidebar and bottom bar links that point at
    a list with **no** query use the saved search when present (read safely in try/catch; fall back to the plain
    link). Scroll is restored after the list renders. Unit-test the storage failing (throws) → plain link.
11. **View transitions** (after step 0): read `view-transitions.md`. Wrap the list row's title and the record header
    title in `<ViewTransition name={`record-${id}`}>` (kit `DataTable` row and `RecordHeader`) so opening a record
    slides the title into place; area changes cross-fade (`<ViewTransition>` around `<main>` with the default
    animation). Durations 180 ms, ease-out. Under `prefers-reduced-motion: reduce` no animation (CSS
    `::view-transition-group(*) { animation: none }` inside the media query). Browser spec: navigation still works
    with transitions on and with reduced motion.
12. **Speed budget.**
    - `scripts/check-desk-bundle.mjs`: after `next build`, read the build's client manifests (find the right file in
      `.next/` for this Next version; read `node_modules/next/dist/docs/` if unsure and write in the PR which file you
      used), sum the gzip size of the JavaScript each `/desk/*` route loads first, compare with
      `scripts/desk-bundle-budget.json` (`{ "<route>": kb }`). The first run writes the file from the measured sizes
      rounded up to the next 10 KB. A route more than 10 % over its budget fails. Run it in the CI build job after
      the build step (edit `.github/workflows/ci.yml`; keep `permissions: contents: read`).
    - `e2e/app-feel.spec.ts`: from Today, clicking Customers shows a skeleton or the `<h1>` within 1000 ms and
      the list within 3000 ms (CI-safe numbers; the real-phone targets in the design are checked on the owner row).
