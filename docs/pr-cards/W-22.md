## W-22B — durable, per-agreement draft allocation (MERGED #399)

**Baseline:** main `f81922fbe3797ed79df60419cfdcdf2fff95b84b` (#398).
Implementation recipe: `docs/implementation-contracts/W-22-PERSISTENCE-RECIPE.md`
(transaction/persistence + provider boundary). Approved Amendment B §6.2;
IN-79 tax gate is not cleared.

- New additive `AgreementSigningCharge`, one row per agreement, separate
  integer-cent fee, per-agreement down payment, credited first-month share,

  Database checks reject negative or unequal subtotals and unknown tax states.
- `prepareDraftSigningChargeSnapshots(userId, agreementId)` rechecks active

  its first sorted agreement, while every individual agreement retains its
  own first-month down-payment share. Retry is idempotent; changed draft
  sources increment version; frozen revisions reject repricing.
- New money is **not collected or settled**. No invoice, receipt, tax charge,
  Stripe API call, customer signing changes, communication or paid action.
  Snapshot preparation is an internal tested domain entrypoint; next slice
  must wire it to a reviewed signing flow and tax-inclusive customer totals.
- Migration and backup manifest added. Real disposable PostgreSQL tests in
  `tests/signing-charge-snapshot-integration.test.ts` cover actor access,
  concurrent/idempotent preparation, multi-address ownership, draft repricing
  and frozen-row protection. Exact-head CI, migration and schema-health tests
  are merge gates; no production seed or customer data is touched.

## W-22C4 — canonical private all-in order draft (MERGED #405)

Baseline: `886e19fa86228eac0866a530e4d8d510c99750bb` (#404).
`assembleSigningOrderDraft` builds a stable SHA-256-fingerprinted,
order-wide **private candidate** from the database's prepared agreement
allocations and independent category-confirmed tax candidate. It requires
matching agreement, address, draft version and order source fingerprints;
no duplicate fee per location, no omitted sibling agreement, integer cents,

`eligibleForSigning: false` and `eligibleForCollection: false`. The owner
agreement screen displays the tentative aggregate only, never a demand for
payment. Focused unit and isolated PostgreSQL tests cover edge cases.
