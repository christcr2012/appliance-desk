- Existing `getFrozenSigningOrderInTx(tx, agreementId)` checks every sibling, customer/address, cents, tax and order digest; `offerMatchesFrozenEvidence` compares signature-specific accepted amount/hash/schema. `buildFrozenSigningCheckoutPlan` (W-22D1) sums exact line kinds with no provider side effect.
- Existing `signAgreement` sets `SignatureRecord.signedAt` and `RentalAgreement.status=ACTIVE`, but `createCheckoutSessionForAgreement` is deliberately blocked for any frozen W-22 agreement until a new provider path exists.
- New `getReviewedSigningPayment(agreementId)` (server-only read): repeatable-read transaction checks active signed nonprepaid agreement with no unreconciled legacy deposit/waiver, verifies the complete frozen order and this immutable signature, returns customerId, agreementId, signedAt and exact agreement-only payment plan. Unchanged settings/browser values are never consulted. Any mismatch fails before external effects; this function has **no Stripe call**, payment collection or paid status.
- Lock and state: repeatable-read snapshot of agreement/signature/order siblings; no mutations or new locks; downstream checkout must separately implement durable provider idempotency and a current-state recheck as required by its reviewed design.
