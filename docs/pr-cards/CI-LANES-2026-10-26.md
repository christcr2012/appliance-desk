# CI-LANES-2026-10-26 — reduce repeat CI cycles across lanes

**Approved scope:** Chris's October 26 request to review lanes 1–8, remove shared CI slowdowns, and improve local test instructions.
**Risk:** CI and developer-tooling only. No runtime, production data, provider, release or approval changes.

## Evidence before implementation

Recent GitHub Actions logs show that:
- In OPS-6 run 40434874127, unit shard 3 passed its test command but ran for 187.38 seconds, exceeding the existing 180-second phase cap. A later successful run 40436840050 used three unit shards with phase times 129.22, 125.16, 98.33 seconds. The variability makes the three-way split brittle.
- CI currently runs five parallel browser groups, yet `scripts/check-ci-layout.mjs` still requires only four; a missing fifth group could pass that guard.
- OPS-4 run 40435294933 failed `tests/acc5-job-role-rules.test.ts` because a new menu path had no job-role screen mapping; it also failed two real browser checks. The quick pre-push route-inventory guard checks only accessibility inventory, not this job-role mapping.
- Other observed red runs include real browser regressions (OPS-4), unit fake mismatch (OPS-4), and secret scanner false positives on merged main (CMP-1; already being addressed separately in PR #643). None may be hidden or quarantined.
- Five browser runners each perform a Next production build. Avoid changing build/artifact topology without measured artifact size and transfer versus build time; this card addresses demonstrated phase overruns and repeat push cycles instead.

## Acceptance criteria, written before code

- [ ] Split the complete Vitest suite from three to four **parallel** runners, each with its own disposable Postgres; `--shard=N/4` covers all files exactly once, keeps schema/upgrade proof on shard 1, no skipped/removed tests and the same 180-second phase budget.
- [ ] Update the CI topology policy to require four unit and five browser groups; make its regression tests detect removed/missing shard entries. Do not weaken the aggregate `ci` gate.
- [ ] Make local preflight run `tests/acc5-job-role-rules.test.ts` when the desk navigation or job-role screen rules change; preserve the existing Today, navigation and route-inventory regressions. Test the selector.
- [ ] Update the short local test guide with exact commands for a safe disposable database, focused tests before push, the custom GitHub tool's job logs/annotations, stale remote main / branch rebuild pitfalls, and when CI is the fallback rather than guessing a local pass.
- [ ] Record a concise, evidenced cross-lane bottleneck summary and next measurement in docs; do not change provider, deployment, production data, secret allowlist or test budget.
- [ ] Focused tests and complete exact-head CI green before merge; disposition every review finding.
