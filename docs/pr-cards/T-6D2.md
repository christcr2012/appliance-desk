## Build contract

Amendment D §15.3–15.4, clarified by BATCH-T’s 2026-10-08 safety reconciliation. Extend each RENTAL/LATE_RETURN EngineInput line with acquisitionBasis?: { applianceId: string; status: AcquisitionTaxStatus; verifiedTaxPaid: boolean }[]. Loader derives evidence; clients cannot set exemption. Split a multi-appliance rental amount deterministically by the assignment covering billingPeriodStart (allocateAcrossLines); outgoing asset owns a swapped mid-period period. Compute state-collected tax per asset then aggregate original line/jurisdiction; preserve InvoiceTaxLine unique identity and cent sum. Home-rule configured rules remain independent.
PAY_ON_ACQUISITION: only verified full sales/use-tax payment qualifies for ≤36-month exemption; UNKNOWN and USE_TAX_DUE return a readiness problem until CPA evidence IN-33 approves a different policy. This deliberately closes §15.3's contradictory 'tax accrued equals paid' assumption; no automatic permission or retroactive re-taxing. Explicit state override cannot bypass missing acquisition evidence. COLLECT_ON_RENTALS retains taxable state rent with recorded permission; no guessed exemption for past purchases. Long leases stay taxable. Missing asset-period assignment blocks affected billing, not unrelated intake/repair.
In markPeriodFiled's existing transaction, update linked APPLIANCE status to USE_TAX_PAID only when paidOn and confirmed payment evidence cover its due tax across all applicable rows. Filing with no payment is not proof of payment. Reconcile PO-sourced rows only through explicit asset mapping; never match by description. All current tax callers must supply the basis or fail with a typed problem for rental lines; update tax-ready fixture helper in the same PR. Historical signed artifacts/invoices are unchanged; expose legacy UNKNOWN as a fixable owner queue.
