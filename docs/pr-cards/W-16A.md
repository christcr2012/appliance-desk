## Build contract

1. **Schema (migration `rental_packages`, additive).** `RentalPackage { id, name @unique, slug @unique,
   monthlyPriceCents Int, showOnWebsite Boolean @default(false), sortOrder Int @default(0), isActive Boolean
   @default(true), photoUrl String?, components, timestamps }`; `RentalPackageComponent { id, packageId (cascade),
   applianceTypeId (restrict), quantity Int @default(1), @@unique([packageId, applianceTypeId]) }`; nullable
   `packageId` (FK, restrict) on `RentalLine`, `EstimateLineItem`, `LeadApplianceRequest`, each indexed. CHECKs:
   price ≥ 0, quantity between 1 and 10.
2. **Moving existing data (same migration).** If an `ApplianceType` with slug `washer-dryer-set` exists: create the
   package "Washer + Dryer Set" (same name, slug, price, website flag, sort order, photo), components = the `washer` and
   `dryer` types that exist (quantity 1 each), point every `LeadApplianceRequest` of that type at the package, then retire
   the type (`isActive = false, showOnWebsite = false`). Idempotent (`ON CONFLICT DO NOTHING`); nothing else changes.
   Signed agreements and their lines are untouched. Appliances still recorded under the retired type are handled by
   W-16B's split To do.
3. **Pure pricing** (`src/domains/packages/pricing.ts`, no database import):
   `separateTotalCents(components: {quantity, monthlyPriceCents}[])`, `packageSaving(setPriceCents, components) →
   { separateCents, savingCents }` (saving may be ≤ 0 — the screen then says "no saving"), `machineCount(components)`,
   `validatePackageInput(input) → string | null` (name 1–100 chars; price $0–$100,000; at least 2 machines in total;
   no duplicate types; quantity 1–10).
4. **Domain** (`src/domains/packages/index.ts`), every write in one transaction with
   `assertActiveTeamActor(tx, userId, ["OWNER","ADMIN"])`, row lock `SELECT … FOR UPDATE` on the package for updates, and
   an AuditLog row: `listPackagesForSettings()`, `createPackage(userId, input)` (unique slug via `slugify` + suffix;
   starts hidden), `updatePackage(userId, id, input)` (name, price, components; components must be active types; a price
   change also writes a `PricingRule` `"<name> — set price"` with old/new), `setPackageVisibility`, `setPackageActive`
   (retiring forces hidden). Any type works — including one added after launch (no type names in code).
   `getPublishedCatalog()` (in `src/domains/pricing/index.ts`): active+published packages whose component types are all
   active, then active+published types, each `{ kind: "package" | "type", id, name, slug, monthlyPriceCents, photoUrl,
   contents?: string, savingCents? }`.
5. **Settings → Products and pricing** gets a **Sets and packages** card above the single machines: each package shows
   its contents, set price (dollars), the automatic sentence "Renting these separately would be $70.00 a month; the set
   is $60.00 — the customer saves $10.00", show-on-website, retire/restore, and an editor (name, price in dollars, one row
   per machine type with a quantity). "Add a set" form below. Plain words explain what a set is (until W-18's ⓘ lands:
   field help text). Server actions OWNER/ADMIN, dollars → cents only in the action.
6. **Website:** pricing page, home catalog grid and city pages use `getPublishedCatalog()`; a package card shows
   "Washer + Dryer" contents and "Save $10.00 a month compared with renting them separately" when the saving is positive.
   The hard-coded `washer-dryer-set` slug check is removed.
7. **Quote form and leads:** the form lists sets first, then single machines (one checkbox each; sets registered as
   `packageIds`). Validation: at least one of either when the catalog is not empty; every id must be published.
   `createLead` stores one `LeadApplianceRequest` per machine type in the set with `packageId` set (quantity × the
   component quantity), so every existing reader keeps working; `summarizeApplianceRequests()` (pure, in
   `src/domains/leads/requests.ts`) groups package rows back into "1x Washer + Dryer Set" for the leads list, lead page and
   the new-lead email.
8. **Seed:** starter catalog = Washer, Dryer + the "Washer + Dryer Set" package (no set type).
